# 06. 利用ガイド

taskapp を自分のマシンで使い始めるまでと、日々の使い方をまとめます。

## 1. インストールと起動

1. リリースから OS に合ったアーカイブ（`taskapp_<version>_darwin_arm64.tar.gz` など）を取得して展開し、`taskapp`（Windows は `taskapp.exe`）を PATH の通った場所に置きます。
2. 起動します。

   ```bash
   taskapp serve
   ```

   - ブラウザで <http://127.0.0.1:7700> を開きます。この PC のブラウザからは、ログインなしでオーナーとして入れます。
   - データは `~/.taskapp/taskapp.db`（SQLite）に保存されます。場所は `--data DIR` か環境変数 `TASKAPP_DATA` で変えられます。
   - 既定では `127.0.0.1` だけで待ち受けます（ほかの端末からは使えません。使うときは「7. ほかの端末から使う」）。ポートは `--port` で変更できます。
   - 起動中は 1 日ごとに自動でバックアップを取ります（`~/.taskapp/backups/`、新しい 7 件を保持）。詳しくは「6. バックアップと復元」。

3. 試しに使うだけなら、デモデータを別の場所に作れます。

   ```bash
   taskapp seed --preset demo --data /tmp/taskapp-demo
   taskapp serve --data /tmp/taskapp-demo
   ```

## 2. 最初の設定

1. **プロジェクトを作る**: サイドバー「プロジェクト」→ 新規。キー（例: `APP`）はイシューのキー（`APP-12`）と Jira 連携に使うので、あとから変えられません。
2. **エージェントを登録する**: 「設定 › メンバーとエージェント」でエージェント（例: `claude`）を追加します。
3. **トークンを発行する**: 「設定 › API トークン」で、エージェント用・ORCA 用のトークンを発行します。発行したトークンは、一覧の目のボタンで後から表示でき、そのまま下の MCP・Jira のコマンドにも入ります（このしくみより前に発行したトークンは表示できないので、発行し直します）。
4. **ステータスやラベルを調整する**: プロジェクトのイシュー一覧で、タイトル横の歯車からプロジェクト設定を開きます。

## 3. エージェント（Claude Code）をつなぐ

「設定 › エージェントの接続（MCP）」に、そのまま実行できるコマンドが出ています。登録先（Claude Code のスコープ）を選ぶと、コマンドが切り替わります。

| スコープ | 保存先 | 使える範囲 |
|---|---|---|
| `user`（画面の既定・おすすめ） | `~/.claude.json` | 自分だけ・すべてのプロジェクト |
| `local`（`--scope` を省略したとき） | `~/.claude.json` のそのディレクトリの欄 | 自分だけ・コマンドを実行したプロジェクトだけ |
| `project` | リポジトリの `.mcp.json`（git で共有） | そのリポジトリを使う全員。トークンは書かず、各自が環境変数 `TASKAPP_TOKEN` に入れる |

```bash
# 同じマシンのエージェント（stdio）
claude mcp add --scope user taskapp -e TASKAPP_TOKEN=<トークン> -- /path/to/taskapp mcp --data ~/.taskapp
# HTTP で接続する場合
claude mcp add --scope user --transport http taskapp http://127.0.0.1:7700/mcp --header "Authorization: Bearer <トークン>"
# project スコープ（.mcp.json にトークンを残さない。先に export TASKAPP_TOKEN=<トークン>）
claude mcp add --scope project --transport http taskapp http://127.0.0.1:7700/mcp --header 'Authorization: Bearer ${TASKAPP_TOKEN}'
# 消す・確かめる
claude mcp remove taskapp -s user
claude mcp list
```

別の PC のエージェントをつなぐときは「7. ほかの端末から使う」を参照してください。

エージェントは次の流れで作業します（MCP のプロンプト `work_on_issue` に手順が入っています）。

1. `list_my_issues` で担当のイシューを取得し、`transition_issue` で着手
2. 判断をしたら `record_checkpoint`（要約・判断・**判断基準**・代替案・確信度・進捗）
3. 人間に確認したいことは `ask_question`（はい/いいえ、OK/NG、単一 / 複数選択、テキスト）
4. `get_question_answers` で回答を読み、作業を続ける
5. ストーリー / フィーチャーができたら `request_acceptance` で受入待ちにする

## 4. ORCA をつなぐ（Jira 互換 API）

ORCA の Settings → Jira で **Cloud** を選び、「設定 › Jira 互換 API（ORCA 連携）」に出ている値を入れます。

| 項目 | 値 |
|---|---|
| サイト URL | `http://127.0.0.1:7700` |
| メールアドレス | トークンを発行したユーザーのメールアドレス（未設定なら `<ユーザー名>@taskapp.local`） |
| API トークン | 発行したトークン |

うまくつながらないときは `taskapp serve --log-requests` で起動すると、届いたリクエストがすべてログに出ます。`scripts/jira-smoke.sh` で、ORCA と同じ流れを curl から確認できます。

## 5. 日々の使い方

| やりたいこと | 場所 |
|---|---|
| 自分の担当・起票・回答待ちの QA を見る | マイタスク（`G` → `M`） |
| エージェントからの質問に答える | QA インボックス（`G` → `Q`）。選択肢を選び、必要なら補足を書く |
| エージェントの判断の経緯を見る | イシュー詳細のアクティビティ（チェックポイント）、エージェント活動（`G` → `E`）。確信度「低」は赤枠 |
| 受入検査をする | 受入検査（`G` → `A`）。基準ごとに OK / NG、総評を書いて合格 / 差し戻し。未完了の子イシューや未回答 QA は一覧で確認できる |
| 全プロジェクトの進み具合を見る | 全体ボード（`G` → `B`）。列はステータスの分類、行はプロジェクト。カードのドラッグで分類を移す（そのプロジェクトの、その分類の最初のステータスになる）。「完了を隠す」で完了・キャンセルの列ごと消える。各行の列の上に、そのプロジェクトの件数（ステータスの内訳つき）が出る。行はティア（★ 注力 → 通常 → 🌱 その他）の段に分かれ、「その他」は最初はたたまれている。「注力のみ」で注力のプロジェクトだけにする |
| 大事なプロジェクトとそうでないものを分ける | プロジェクトのティアを決める: 全体ボードの行の見出し・プロジェクト一覧のカードの印（★ / ○ / 🌱）を押す、またはプロジェクト設定 › ティア。**注力** = いま力を入れているもの、**通常** = ときどき進めるもの、**その他** = 優先度は低め・気軽に始めてみたもの |
| 何のために作るのかを整理する | プロジェクトのイシュー一覧の「ストーリーマップ」。左の「ペルソナ・ジョブ」で誰がどんな場面で使うかを書き、活動 → 手順を横に並べ、手順の下にストーリーを置く（行はリリース）。ストーリーを開いて受け入れ条件（Given / When / Then）を書き、作業のイシューをキーでつなぐ。カードの色: 灰 = 条件なし、白 = 着手可能、黄 = 実装中、緑 = 完了。「抜け」でつながっていないものが分かる。イシュー詳細には「満たすストーリー」が出る |
| 全体像を見る | イシュー一覧の「マップ」。ノードのドラッグで親を付け替え、PNG で保存 |
| エピック / ストーリーの進み具合を見る | イシュー一覧の「ロードマップ」 |
| よく使う条件を保存する | フィルタバーの「ビューを保存」→ サイドバー「ビュー」 |
| どこへでも移動・イシューを探す | `⌘K`（Windows / Linux は `Ctrl+K`）のコマンドパレット。`?` でショートカット一覧 |

### 5.1 どこまで使えるか（利用状況と上限）

オーナーは「設定 › 利用状況と上限」で、いまのデータが、動作を確かめた規模のどこまで来ているかを見られます。70% で黄色、90% で赤になります。上限を超えても止まりはしませんが、次のようになります。

| 項目 | 上限 | 超えたとき |
|---|---|---|
| イシュー（全体） | 1 万件（一覧・フィルタが 0.3 秒以内であることを確かめた規模） | 動くが、遅くなっていないか確かめる |
| 全体ボード・一覧に一度に出せる数 | 2,000 件 | 絞り込まない全体ボードや一覧は先頭 2,000 件だけになり、画面の上にお知らせが出る。「完了を隠す」やフィルタで絞る |
| 最大のプロジェクト | 1,000 件（マインドマップの操作を確かめた規模） | マップが重くなる。ルートをエピックにして開く |
| ディスク | ディスク全体 | 1 万件でデータベースは約 9 MB。バックアップはその 10 倍ほど（自動 7 件と起動前 3 件） |

## 6. バックアップと復元

### 6.1 自動バックアップ（既定で有効）

`taskapp serve` は起動したときと、その後 **1 日ごと** に SQLite ファイルの複製を取ります。何も設定しなくても動きます。

| 項目 | 既定 | 変えるとき |
|---|---|---|
| 保存先 | `<データディレクトリ>/backups/`（既定は `~/.taskapp/backups/`） | `--backup-dir DIR`（外付けディスクやクラウド同期フォルダなど） |
| 間隔 | 24 時間 | `--backup-interval 6h`（`30m`、`12h` などの書き方。`0` で自動バックアップを止める） |
| 保持数 | 新しい 7 件 | `--backup-keep 30`（`0` ですべて残す） |

```bash
# 例: 6 時間ごとに iCloud Drive に取り、30 件残す
taskapp serve --backup-interval 6h --backup-keep 30 \
  --backup-dir ~/Library/Mobile\ Documents/com~apple~CloudDocs/taskapp-backups
```

- ファイル名は `taskapp-YYYYMMDD-HHMMSS.db` です。そのまま SQLite のデータベースとして開けます。
- 前回のバックアップから **データが変わっていないときは取りません**。しばらく使わなかった間に、古いバックアップが同じ内容のもので押し出されることはありません。
- 保持数を超えた古いものから消します。消すのは上の名前のファイルだけで、同じフォルダの他のファイルには触れません。
- 書き込み中のファイルは `….db.tmp` という名前で、完成してから名前を変えます。途中で止まっても壊れたバックアップは残りません。
- 状態は **設定 › データ › 自動バックアップ** で見られます（有効 / 無効、保存先、最新と次回の確認時刻、ファイル一覧）。「今すぐバックアップ」で、その場で 1 件取れます。
- 失敗したときは、同じ欄とサーバーのログに理由が出ます。

### 6.2 手動のバックアップとエクスポート

| 方法 | コマンド | 用途 |
|---|---|---|
| バックアップ | `taskapp backup`（自動と同じフォルダへ）/ `taskapp backup --out FILE` | SQLite ファイルの複製。起動したままで取れる。手動のときは古いバックアップを消さない |
| エクスポート | `taskapp export --out taskapp.json`（画面: 設定 › データ） | 全データの JSON。別のマシンへの移行や、中身を確認したいときに |

エクスポートには ID と API トークン（ハッシュ）も含まれるので、復元後もエージェントや ORCA の接続がそのまま使えます。外部に渡すときは注意してください。ログイン用のパスワードは含まれないので、取り込んだあとに設定し直してください（バックアップ・復元では残ります）。

### 6.3 復元

**バックアップ（.db）から戻す**

1. `taskapp serve` を止めます（起動中は `restore` が断ります）。MCP（stdio）で接続しているエージェントも止めてください。
2. 戻したいファイルを指定して実行します。設定 › データ の欄に、最新のバックアップを指定したコマンドが出ています。

   ```bash
   taskapp restore --from ~/.taskapp/backups/taskapp-20261012-090000.db
   ```

3. `taskapp serve` で起動し直します。

- いまのデータは `taskapp.db.before-restore-<日時>` として同じディレクトリに残ります。戻しすぎたときは、これを `--from` に指定して戻せます。
- 古いバージョンで取ったバックアップは、復元のときに今のスキーマへ更新されます。新しいバージョンで取ったものは断ります（先に taskapp を更新してください）。

**エクスポート（.json）から戻す**

```bash
taskapp import --data <新しいディレクトリ> --in taskapp.json   # 空のデータディレクトリにだけ取り込める
taskapp serve --data <新しいディレクトリ>
```

## 7. ほかの端末から使う

スマホや別の PC から画面を見たり、別の PC のエージェントを MCP でつないだりできます。サーバーはデータのある PC で 1 つだけ動かし、ほかの端末はそこへ接続します。

> **通信は暗号化されません。** 自宅・社内の信頼できるネットワークか、Tailscale などの VPN の中だけで使ってください。インターネットに直接公開しないでください。

### 7.1 外から接続できるように起動する

```bash
taskapp serve --host 0.0.0.0
```

- 起動時に警告が出ます（暗号化されないこと、まだ誰もパスワードを持っていなければそのこと）。
- 「設定 › ほかの端末から使う」に、ほかの端末で開く URL（例: `http://192.168.1.10:7700`）が出ます。
- Tailscale を使う場合は、その PC の Tailscale の IP（`100.x.y.z`）か MagicDNS の名前で開けます。
- macOS ではファイアウォールの確認が出ることがあります。許可してください。

### 7.2 パスワードを設定する

ほかの端末からはパスワードでログインします（パスワードなしで入れるのはこの PC のブラウザだけです）。

- **自分の分**: この PC で「設定 › アカウント」から設定します（8 文字以上）。
- **ほかの人の分**（オーナーのみ）: 「設定 › メンバーとエージェント」の各行の「パスワードを設定」。
- **コマンドで**: `taskapp passwd --user <ユーザー名>`（サーバーが動いたままでもすぐ効きます。`--clear` で解除）。

エージェントはパスワードを持てません。API トークンを使います。

### 7.3 ほかの端末で画面を開く

1. 7.1 の URL を開くと、ログイン画面が出ます。
2. ユーザー名とパスワードを入れます。オーナー以外の人には、データ（バックアップ・エクスポート）などオーナー用の設定は出ません。
3. 「ログインしたままにする（30 日）」を選ぶと、ブラウザを閉じても 30 日ログインが続きます（使うたびに延びます）。選ばないときは、ブラウザを閉じるか 1 日使わないとログアウトします。どちらもサーバーの再起動（デプロイ）ではログアウトしません。
4. サイドバー下のボタンでログアウトできます。共用の端末では「ログインしたままにする」を選ばないでください。

パスワードを 5 回続けて間違えると、その端末からは 1 分間ログインできません。

### 7.4 別の PC のエージェントをつなぐ

「設定 › エージェントの接続（MCP）」の「HTTP（ほかの端末のエージェント）」にあるコマンドを、その PC で実行します。

```bash
claude mcp add --transport http taskapp http://192.168.1.10:7700/mcp --header "Authorization: Bearer <トークン>"
```

トークンはエージェントごとに発行してください。stdio（`taskapp mcp`）は同じ PC 専用です。ORCA を別の PC で使う場合も、サイト URL をこの URL にします。

### 7.5 この PC でもパスワードを必須にする

`taskapp serve --require-login` で起動すると、この PC からもログイン画面になります。

### 7.6 リバースプロキシの後ろで動かす（tailscale serve など）

同じマシンのプロキシに HTTPS をまかせる場合は、`127.0.0.1` で待ち受けて `--behind-proxy` を付けます。

```bash
taskapp serve --behind-proxy --public-url https://task.<tailnet名>.ts.net
tailscale serve --bg 7700
```

- これがないと、プロキシ経由の MCP（HTTP）は 403 になります。
- この PC のブラウザからもログイン画面になります（プロキシ経由だと、この PC かどうかを見分けられないため）。先に `taskapp passwd` でパスワードを設定してください。
- `--public-url` の URL が「設定 › ほかの端末から使う」と MCP のコマンドに出ます。
- サービス用のユーザーで動かすときは、環境変数 `TASKAPP_OWNER` でオーナーのユーザー名を決めます（初回の起動時だけ使われます）。

## 8. 困ったとき

| 症状 | 対処 |
|---|---|
| 画面が古いまま | 変更は自動で反映されます（SSE）。サーバーを再起動した直後は数秒で再接続します |
| エージェントが `invalid token` になる | トークンが失効していないか「設定 › API トークン」で確認し、発行し直す |
| ORCA が 404 を返す | 7700 番で古いバイナリが動いていないか確認する（`/rest/api/3/myself` が返るか） |
| ポートが使われている | `taskapp serve --port 7701` |
| 自動バックアップが増えない | データが変わっていなければ取りません（正常）。設定 › データ で「無効」なら `--backup-interval 0` で起動しています |
| `restore` が「stop it first」で止まる | 同じデータディレクトリで `taskapp serve` が動いています。止めてから実行してください |
| ほかの端末から開けない | `--host 0.0.0.0` で起動しているか、同じネットワーク（または VPN）にいるか、ファイアウォールで止められていないかを確認する |
| ほかの端末でログインできない | 「設定 › メンバーとエージェント」でその人が「パスワード設定済み」か確認する。5 回続けて間違えたときは 1 分待つ |
| この PC で毎回ログイン画面になる | ログアウトしたあとです。ログイン画面の「このPCのオーナーとして入る」で戻ります。`--require-login` か `--behind-proxy` で起動していないかも確認する |
| プロキシ経由の MCP が 403 になる | `--behind-proxy` を付けて起動する（7.6） |
