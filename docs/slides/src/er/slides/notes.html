採番・ID・並び順のルール

階層

親子規則と循環禁止はサービス層で検証。親と子の project_id は一致させる

キー採番

作成時、同じトランザクションで projects.next_issue_number を UPDATE … RETURNING して number と key を決める。キー変更は当面不可

jira_id

Jira API は数値の id を返すため、ULID とは別に連番の数値 ID を持つ（projects・issues・comments・attachments）

sort_order

兄弟の並び。ドラッグ時は前後の値の中間値を入れる（fractional index）
