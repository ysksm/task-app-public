06 · 設計判断 ① 階層

階層は1テーブルの自己参照で持つ

  • issues.parent_id で親を表す。種別ごとの親子規則はサービス層の CanBeChild で検証
  • 規則はプロジェクト設定（スキップ許可）で変わるため DB 制約にしない
  • 子孫の取得と進捗集計は再帰 CTE でクエリ時に計算。更新時の集計値は持たない
  • 親付け替え時は、新しい親の祖先に自分がいないかを再帰 CTE で確認（循環防止）
  • 1万件で遅ければ issue_closure テーブルの導入を検討

WITH RECURSIVE tree(id, depth) AS (
  SELECT id, 0 FROM issues
   WHERE id = :root
  UNION ALL
  SELECT i.id, t.depth + 1
    FROM issues i
    JOIN tree t ON i.parent_id = t.id
)
SELECT ... FROM tree
