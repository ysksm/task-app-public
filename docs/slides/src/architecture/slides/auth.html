09 · 設計判断 ④ 認証とリアルタイム

誰が・どこから変えたかを必ず記録する

経路認証方式
Web UI（この PC）オーナーとして自動ログイン（HttpOnly Cookie）
Web UI（ほかの端末）人間のユーザー名 + パスワード
Jira 互換 APIBasic（メール + API トークン）または Bearer
MCP HTTPBearer PAT（別の PC からも可）
MCP stdio環境変数 TASKAPP_TOKEN

認証はトークンの SHA-256 と、パスワードの PBKDF2-SHA256 のハッシュ。トークンは後から表示できるよう AES-256-GCM の控えも保存（鍵は data/token.key、表示はオーナーと持ち主だけ）。セッションは DB に Cookie の値のハッシュだけを保存（再起動してもログインが続く。最後の使用から 1 日、「ログインしたままにする」で 30 日）。5 回続けて失敗すると 1 分間 429。実行者（ユーザー + 経路）は履歴に記録

SSE で即時反映

サービス層が変更確定後にイベントを発行 → SSE → UI はキャッシュを無効化して再取得

自動ログインはこの PC だけ

接続元と Host の両方がループバックのときだけ。DNS リバインディングや PC 上のプロキシ経由はログイン画面へ。--behind-proxy では自動ログインも止める
