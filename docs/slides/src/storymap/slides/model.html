種類ごとに連番のキー。消さずにアーカイブ、変更は履歴に残す

種類キーの例テーブル
ペルソナTAPP-P1req_personas
ジョブTAPP-J3req_jobs
活動TAPP-A1req_activities
手順TAPP-A1-2req_steps
ストーリーTAPP-ST12req_stories

つながり：req_job_activities（ジョブ ⇄ 活動）、req_story_steps（ストーリー ⇄ 手順）、req_story_issues（ストーリー ⇄ イシュー）。どれも N:N

キーの採番：req_counters（プロジェクト × 種類）。アーカイブしてもキーは使い回さない

リリース：ストーリーの release（自由な文字列、例 R1）。マップの横線はこの値でまとめる

受け入れ条件：given / when / then の 3 つの欄。M2 でテストのタグ（@TAPP-AC42）につなぐ
