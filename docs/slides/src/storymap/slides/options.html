09 · 決めたいこと: 今の「受入基準」との関係

要求は新しいテーブルに持ち、イシューから「つなぐ」（案 A）

案 A（おすすめ）新しいテーブル

ストーリー（L5）と受け入れ条件（L6）は新しいテーブル。イシューはストーリーにつながる。
イシューの受入基準は「その回の実装で確かめること」として今のまま。

長所：イシューが Done になっても要求は残る。受入検査を壊さない
短所：「受け入れ条件」と「受入基準」の 2 つの言葉。画面で区別が要る

案 B 今の仕組みを使う

ストーリー = 今の「ストーリー」種別のイシュー、受け入れ条件 = 今の受入基準に Given/When/Then を足す。

長所：追加が少ない
短所：ストーリーのイシューが Done で閉じると、要求も閉じたことになる。「要求は生き続ける」と合わない

案 A では、イシューの受入基準を作るときに「つながっているストーリーの受け入れ条件から写す」ボタンを付ける（写すだけで、同期はしない）
