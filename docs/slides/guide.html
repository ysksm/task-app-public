USER GUIDE

利用ガイド

インストールから、エージェント・ORCA の接続、日々の使い方、ほかの端末からの利用まで

AIエージェントと人間のタスク管理アプリ

2026-10-12

01 · インストール

単一バイナリを置いて起動するだけ

$ taskapp serve
# → http://127.0.0.1:7700
#   この PC のブラウザはログインなし
#   既定は 127.0.0.1 だけで待ち受け

# デモデータで試す
$ taskapp seed --preset demo --data /tmp/demo
$ taskapp serve --data /tmp/demo

配布物

macOS / Linux / Windows（amd64・arm64）のアーカイブ。Web UI も中に入っている

データ

~/.taskapp/taskapp.db（SQLite）。--data か TASKAPP_DATA で変更

2 / 10

02 · 最初の設定

プロジェクト・エージェント・トークンを用意する

1. プロジェクト

キー（例: APP）はイシューのキーと Jira 連携に使うため変更不可

2. エージェント

設定 › メンバーとエージェントで claude などを追加

3. トークン

設定 › API トークンで発行。目のボタンで後から表示でき、MCP・Jira のコマンドにも入る

4. ステータス・ラベル

イシュー一覧の歯車からプロジェクト設定

3 / 10

03 · エージェントをつなぐ（MCP）

Claude Code に登録すれば、判断と確認が残る

$ claude mcp add --scope user taskapp -e TASKAPP_TOKEN=<トークン> -- taskapp mcp
# --scope  user: 自分・全プロジェクト / local: このプロジェクトだけ
#          project: .mcp.json で共有（トークンは ${TASKAPP_TOKEN}）

着手

list_my_issues → transition_issue

判断を残す

record_checkpoint（判断基準・確信度・進捗）

人間に聞く

ask_question → get_question_answers

仕上げ

request_acceptance で受入待ちへ

4 / 10

04 · ORCA をつなぐ（Jira REST API v3）

Jira 連携の Cloud モードにそのまま登録する

ORCA の項目入れる値
接続方式Cloud
サイト URLhttp://127.0.0.1:7700
メールアドレストークンのユーザーのメールアドレス（未設定なら ユーザー名@taskapp.local）
API トークン設定 › API トークンで発行したもの

つながらないときは taskapp serve --log-requests で ORCA のリクエストを記録。scripts/jira-smoke.sh で同じ流れを curl から確認できる

5 / 10

05 · 日々の使い方

⌘K でどこへでも、G → 文字キーで主要画面へ

やりたいこと場所
自分の担当を見るマイタスク（G → M）
全プロジェクトを見る全体ボード（G → B）。列は分類、行はプロジェクト（★注力 → 通常 → 🌱その他の段。「注力のみ」で絞る）
エージェントの質問に答えるQA インボックス（G → Q）
判断の経緯を見るイシュー詳細のチェックポイント / エージェント活動（G → E）
受入検査をする受入検査（G → A）
全体像を見る・付け替えるイシュー一覧の「マップ」（ドラッグで親を変更、PNG 保存）
条件を保存するフィルタバーの「ビューを保存」
どこまで使えるか見る設定 › 利用状況と上限（オーナー）。1 万件・2,000 件・1,000 ノード・ディスクへの到達率
何のために作るか整理するイシュー一覧の「ストーリーマップ」。ペルソナ・ジョブ、活動 → 手順、ストーリーと受け入れ条件、イシューをつなぐ

6 / 10

06 · 自動バックアップ

起動しておくだけで、1 日ごとに複製が残る

項目既定変えるとき
保存先~/.taskapp/backups/--backup-dir DIR
間隔24 時間--backup-interval 6h（0 で停止）
保持数新しい 7 件--backup-keep 30（0 ですべて）

ファイル名は taskapp-YYYYMMDD-HHMMSS.db。データが変わっていないときは取らないので、使わない間に古い世代が押し出されない

画面で確認

設定 › データ。保存先・最新・次回の確認時刻・一覧。「今すぐバックアップ」でその場で 1 件

手動でも

taskapp backup（同じフォルダへ）。全データの JSON は taskapp export

7 / 10

07 · 復元

サーバーを止めて、restore で戻す

# 1. taskapp serve を止める
# 2. バックアップ（.db）から戻す
$ taskapp restore --from \
    ~/.taskapp/backups/taskapp-20261012-090000.db
# 3. 起動し直す
$ taskapp serve

# エクスポート（.json）からは空のディレクトリへ
$ taskapp import --data ~/.taskapp-new --in taskapp.json

いまのデータは残る

taskapp.db.before-restore-<日時> として退避。戻しすぎたらこれを --from に

安全のために

起動中は断る。taskapp の DB でないファイルや、新しいバージョンのバックアップも断る

8 / 10

08 · ほかの端末から使う

--host で開き、ほかの端末はパスワードでログイン

# 1. 外から接続できるように起動
$ taskapp serve --host 0.0.0.0
# 2. パスワードを設定（設定 › アカウントでも可）
$ taskapp passwd --user kasa
# 3. スマホ・別の PC で開いてログイン
#    http://192.168.1.10:7700
# 4. 別の PC のエージェント（MCP HTTP）
$ claude mcp add --transport http taskapp \
    http://192.168.1.10:7700/mcp \
    --header "Authorization: Bearer <トークン>"

パスワードの設定

自分: 設定 › アカウント。ほかの人: オーナーがメンバー一覧から。コマンド: taskapp passwd

暗号化されない

自宅・社内の LAN か Tailscale などの VPN の中だけで。パスワードなしで入れるのはこの PC だけ

9 / 10

09 · リバースプロキシの後ろで動かす

tailscale serve の後ろでは --behind-proxy

# 1. 127.0.0.1 で待ち受け、プロキシの後ろと伝える
$ taskapp serve --behind-proxy \
    --public-url https://task.<tailnet名>.ts.net
# 2. HTTPS はプロキシにまかせる
$ tailscale serve --bg 7700
# 3. 先にパスワードを設定（自動ログインは止まる）
$ taskapp passwd --user kasa
# サービス用ユーザーで動かすときはオーナー名を指定
$ TASKAPP_OWNER=kasa taskapp serve --behind-proxy ...

付けないと MCP が 403

プロキシ経由の MCP（HTTP）は、DNS リバインディング対策で断られる。トークンは付けても必須のまま

この PC でもログイン画面

プロキシ経由だと、この PC かどうかを見分けられないため。--public-url の URL が設定画面と MCP のコマンドに出る

10 / 10
