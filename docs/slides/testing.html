02 · 流し方

make で流す。一部だけなら各ディレクトリで

$ make test       # 単体 + API（10 秒ほど）
$ make test-e2e   # 画面（Web UI ごとビルド）

# 初回だけ: ブラウザを入れる
$ cd e2e && pnpm exec playwright install chromium

# 一部だけ
$ cd e2e && pnpm exec playwright test tests/map.spec.ts
$ cd e2e && pnpm exec playwright test -g "drag"

# 別の実装を確かめる
$ make test-e2e TASKAPP_BIN=/path/to/taskapp

前提

Go 1.24+、Node 22+、pnpm。最初に pnpm install

並列に流れる

テストごとに demo データ入りのサーバーを空きポートで起動するので、互いに影響しない

03 · 失敗したとき

スクリーンショットとトレースで、そのときの画面を見る

やりたいことコマンド（e2e/ の中で）
失敗の一覧と画面・トレースpnpm exec playwright show-report
1 件のトレース（操作ごとの画面・DOM・通信）pnpm exec playwright show-trace test-results/…/trace.zip
ブラウザを表示しながらpnpm exec playwright test --headed
1 ステップずつ止めながらpnpm exec playwright test --debug -g "名前"
不安定なテストを探すpnpm exec playwright test --repeat-each=5

失敗したテストの記録は e2e/test-results/ に残る（git には入らない）

04 · 画面テストの書き方

画面で操作し、API でも結果を確かめる

import { expect, test } from "../fixtures.js";

test("担当を変えるとマイタスクから消える",
  async ({ page, demo }) => {
  await page.goto("/my");
  await expect(page.getByText("Jira互換API")).toBeVisible();
  // エージェントとしての操作も API で書ける
  await demo.api("claude").patch(
    "/api/v1/issues/APP-12", { assignee: "claude" });
  await expect(page.getByText("Jira互換API")).toHaveCount(0);
});

demo.api(who)

owner / alice / claude / codex として API を呼ぶ

peek(page)

右の詳細パネル。data-issue-key で開いているイシューを確かめる

05 · 書くときの決まり

文言とロールで探し、待ってから数える

文言とロールで探す

getByRole("button", { name: "回答する" })。CSS クラスに頼らない。data-testid は特定しにくい所だけ

API でも確かめる

画面の表示だけでは保存されたか分からない。expect.poll で反映を待つ

待ってから数える

.all() は待たない。先に expect で表示を待つ。時刻の表示は確かめない

確認ダイアログ

window.confirm は自動でキャンセルされる。必要なら page.once("dialog", d => d.accept())

API テストは apitest/

startServer({ preset, setup, serveArgs })。形は assertOperation で OpenAPI と照合
