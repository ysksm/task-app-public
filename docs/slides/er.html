11 · 設計メモ

採番・ID・並び順のルール

階層

親子規則と循環禁止はサービス層で検証。親と子の project_id は一致させる

キー採番

作成時、同じトランザクションで projects.next_issue_number を UPDATE … RETURNING して number と key を決める。キー変更は当面不可

jira_id

Jira API は数値の id を返すため、ULID とは別に連番の数値 ID を持つ（projects・issues・comments・attachments）

sort_order

兄弟の並び。ドラッグ時は前後の値の中間値を入れる（fractional index）

13 · 代表的なクエリ

子孫の進捗と循環チェックは再帰 CTE

子孫と進捗（ツリー・マップ）

WITH RECURSIVE tree(id, depth) AS (
  SELECT id, 0 FROM issues
   WHERE id = :root AND deleted_at IS NULL
  UNION ALL
  SELECT i.id, t.depth + 1
    FROM issues i JOIN tree t
      ON i.parent_id = t.id
   WHERE i.deleted_at IS NULL
)
SELECT COUNT(*) AS descendants,
  SUM(s.category IN
   ('completed','canceled')) AS done
FROM tree t JOIN issues i ON i.id = t.id
JOIN workflow_states s ON s.id = i.state_id
WHERE t.depth > 0;

循環チェック（付け替え前）

WITH RECURSIVE ancestors(id) AS (
  SELECT :new_parent
  UNION ALL
  SELECT i.parent_id FROM issues i
    JOIN ancestors a ON i.id = a.id
   WHERE i.parent_id IS NOT NULL
)
SELECT EXISTS (
  SELECT 1 FROM ancestors
   WHERE id = :child
);  -- 1 なら循環
