10 · 置き換え可能性 ①

Rust に置き換えても同じテストが通るように

契約内容置き場所
内部 API/api/v1 の OpenAPI。UI とテストの TS 型を生成api/openapi.yaml
Jira 互換 APIエンドポイント表と期待 JSON のゴールデンapitest/fixtures/jira/
MCPツール名・入力 JSON Schema・出力形式apitest/fixtures/mcp/
DB スキーマ素の SQL マイグレーション（goose Up/Down）internal/store/migrations/
CLIサブコマンドと出力形式（次のスライド）docs/05 §3

契約は言語に依存しない形で持つ。実装を差し替えても、契約とテストはそのまま残る

11 · 置き換え可能性 ②

テストハーネスは CLI の契約だけを使う

taskapp serve --data <dir> --port 0
  → stdout: {"event":"ready","addr":"127.0.0.1:NNNNN"}
taskapp migrate --data <dir>
taskapp seed    --data <dir> --preset demo|test
taskapp token create --data <dir> --user <u> --name <n>
  → stdout: 生のトークン 1 行
taskapp mcp     --data <dir>   # TASKAPP_TOKEN で認証
taskapp backup  --data <dir> [--out <file>]
taskapp restore --data <dir> --from <file>
taskapp passwd  --data <dir> --user <u>  # stdin 1 行
serve --backup-interval 24h --backup-keep 7
serve --host 0.0.0.0 [--require-login]
serve --behind-proxy [--public-url <url>]
TASKAPP_OWNER=<u>  # 初回に作るオーナーの名前

層Rust 置き換え時
API テスト（主）そのまま流用（TASKAPP_BIN を差し替え）
単体テスト実装と一緒に書き直す
画面テスト（e2e/）そのまま流用（同じハーネス）

テストは毎回空のデータディレクトリで起動し、決まったデータ（API: test、画面: demo）を使う

12 · リスクと対策

先に見えている5つのリスク

リスク影響対策
ORCA が想定外の API を要求接続できない--log-requests で通信を記録し不足を追加。ORCA のバージョンを記録
ORCA が Feature / Question や深い階層を想定していない表示が崩れる種別名の対応付けを設定可能に（例: Feature → Story）
未対応の JQL 構文検索エラーJira と同じ文言の 400 を返し、ORCA のテキスト検索に任せる
stdio MCP と serve の同時書き込みロック競合WAL + busy_timeout、書き込みトランザクションを短く
マインドマップの大規模表示描画が重い初期は2階層まで展開、折りたたみ、画面外は描かない
