06 · 設計判断 ① 階層

階層は1テーブルの自己参照で持つ

  • issues.parent_id で親を表す。種別ごとの親子規則はサービス層の CanBeChild で検証
  • 規則はプロジェクト設定（スキップ許可）で変わるため DB 制約にしない
  • 子孫の取得と進捗集計は再帰 CTE でクエリ時に計算。更新時の集計値は持たない
  • 親付け替え時は、新しい親の祖先に自分がいないかを再帰 CTE で確認（循環防止）
  • 1万件で遅ければ issue_closure テーブルの導入を検討

WITH RECURSIVE tree(id, depth) AS (
  SELECT id, 0 FROM issues
   WHERE id = :root
  UNION ALL
  SELECT i.id, t.depth + 1
    FROM issues i
    JOIN tree t ON i.parent_id = t.id
)
SELECT ... FROM tree

08 · 設計判断 ③ 記録

チェックポイント・QA・受入の持ち方

チェックポイント = 専用テーブル

判断基準・確信度・進捗率などの構造化項目を持ち、活動フィードや「確信度低」で横断検索する。Jira API からは [Checkpoint] 付きコメントとして見せる

QA = 種別 + 拡張テーブル

担当・ステータス・コメント・ORCA での表示などチケットの機能をそのまま使う。背景・暫定判断・ブロッキングは 1:1 の qa_details、質問と回答は 1:N の qa_items に持つ

受入 = ステータス + 記録

「受入待ち」は started カテゴリのステータス（ボードの1列）。基準は acceptance_criteria、判定は acceptance_reviews と基準ごとの結果に残す

09 · 設計判断 ④ 認証とリアルタイム

誰が・どこから変えたかを必ず記録する

経路認証方式
Web UI（この PC）オーナーとして自動ログイン（HttpOnly Cookie）
Web UI（ほかの端末）人間のユーザー名 + パスワード
Jira 互換 APIBasic（メール + API トークン）または Bearer
MCP HTTPBearer PAT（別の PC からも可）
MCP stdio環境変数 TASKAPP_TOKEN

認証はトークンの SHA-256 と、パスワードの PBKDF2-SHA256 のハッシュ。トークンは後から表示できるよう AES-256-GCM の控えも保存（鍵は data/token.key、表示はオーナーと持ち主だけ）。セッションは DB に Cookie の値のハッシュだけを保存（再起動してもログインが続く。最後の使用から 1 日、「ログインしたままにする」で 30 日）。5 回続けて失敗すると 1 分間 429。実行者（ユーザー + 経路）は履歴に記録

SSE で即時反映

サービス層が変更確定後にイベントを発行 → SSE → UI はキャッシュを無効化して再取得

自動ログインはこの PC だけ

接続元と Host の両方がループバックのときだけ。DNS リバインディングや PC 上のプロキシ経由はログイン画面へ。--behind-proxy では自動ログインも止める

11 · Jira 互換レイヤー（REST API v3）

v3 固有の対応: ADF・accountId・新しい検索

項目v3 での扱い
説明・コメントADF（JSON の文書ツリー）。内部は Markdown のまま保存し、internal/jira/adf で相互変換
ユーザーaccountId = 内部ユーザー ID。accountType は人間 atlassian / エージェント app
検索POST/GET /search/jql。nextPageToken と isLast でページング
プロジェクトGET /project/search（startAt / maxResults / isLast / values）
認証Basic（メール + API トークン）。ORCA の Cloud モードはこの方式のみ。失敗は必ず 401
ID・応答id は数値（jira_id）。更新・遷移は 204 本文なし。JQL エラーは「Error in the JQL Query」

ORCA は Cloud モードでも接続先 URL を限定しないため、http://127.0.0.1:7700 をそのまま登録できる

12 · テスト戦略

同じ API テストが通れば、Rust 版でも同じ振る舞い

API テスト（主）

apitest/ · TypeScript + Vitest。$TASKAPP_BIN を起動して /api/v1・Jira 互換・MCP を叩く。Rust 版にもそのまま使える

単体テスト

Go testing。階層規則・JQL パーサ・Filter → SQL。実装と一緒に書き直す

画面テスト

e2e/ · Playwright。同じくバイナリを起動してブラウザで操作し、結果を API で確かめる。そのまま使える

言語非依存の契約

  • 内部 API: api/openapi.yaml
  • Jira 互換: ゴールデン JSON
  • MCP: ツールの JSON Schema
  • DB: 素の SQL マイグレーション
  • CLI: serve / seed / token / backup / restore の入出力

13 · 運用

起動・MCP 登録・バックアップ

# データディレクトリ: ~/.taskapp/taskapp.db
taskapp serve --port 7700 --data ~/.taskapp
taskapp serve --host 0.0.0.0  # ほかの端末から（画面はパスワード）
taskapp serve --behind-proxy --public-url https://task.example.ts.net  # tailscale serve の後ろ

# MCP 登録（Claude Code）
claude mcp add taskapp -e TASKAPP_TOKEN=tk_xxx -- taskapp mcp
claude mcp add --transport http taskapp http://127.0.0.1:7700/mcp \
  --header "Authorization: Bearer tk_xxx"

# 自動バックアップ（既定: 24h ごと・7 件・<data>/backups）
taskapp serve --backup-interval 6h --backup-keep 30
taskapp backup                 # 手動（同じフォルダへ）
taskapp restore --from FILE    # 停止中に戻す
