# ✅ 確認: ログインを保持する（追加作業 A-7）

デプロイのたびにログアウトされ、毎回パスワードを入れ直す必要がありました。これをなくすための変更です。ブランチは `feat/remember-login` です。

## 原因

ログイン状態（セッション）を、サーバーのメモリにだけ持っていました。そのため、デプロイでサーバーが再起動すると消えていました。

## 入れたもの

| 項目 | 内容 |
|---|---|
| セッションを DB に保存 | 新しいテーブル `sessions`（マイグレーション 007）に、Cookie の値の SHA-256 だけを保存する。値そのものは保存しない。**再起動（デプロイ）してもログインが続く** |
| 「ログインしたままにする（30 日）」 | ログイン画面のチェック。選ぶと、最後に使ってから 30 日ログインが続く。Cookie に有効期限を付けるので、ブラウザを閉じても残る。選んだかどうかはそのブラウザが覚え、次も同じにする |
| 選ばないとき | 最後に使ってから 1 日、またはブラウザを閉じるまで（今までと同じく、ブラウザを閉じると消える Cookie） |
| 期限の延長 | 使うたびに延びる。DB への書き込みは 10 分に 1 回まで。「ログインしたままにする」のときは、延ばすたびに Cookie も送り直し、ブラウザ側の期限も延ばす（ログインから 30 日で切れないように） |
| https のとき | Cookie に `Secure` を付ける（Tailscale の https 経由など）。今の http の LAN では付けない。付けると、ブラウザが Cookie を捨ててしまうため |
| そのほか | ログアウトでそのセッションを消す。パスワードを変えると、その人のほかのセッションも消す（今までと同じ）。JSON のエクスポートには入れない |

## 確認済みのこと

- API テスト 185 件（+3 件）、画面テスト 32 件（+1 件）、Go の単体テスト（期限の延長と切れ方。時計を進めて確かめる）がすべて成功した。
- API テストで確かめたこと（テスト用のサーバーを途中で再起動できるようにした）:
  - 「ログインしたままにする」の有無にかかわらず、再起動したあともログインが続く。
  - 選んだときだけ、Cookie に 30 日の `Max-Age` が付く。
  - http では `Secure` を付けず、https のプロキシ経由では付ける。
  - ログアウトしたセッションは、再起動したあとも使えない。偽の Cookie は 401 になる。
  - エクスポートに `sessions` が入らない。
- 画面テストで確かめたこと:
  - チェックを入れてログインすると、Cookie の期限が 30 日先になる。
  - 再起動したあとも、ログインしたまま画面を開ける。
  - 次にログイン画面を開いたとき、チェックが入ったままになっている。

## 確認できていないこと

- `tailscale serve` 経由で、Cookie に `Secure` が付くか。テストでは、`X-Forwarded-Proto: https` を付けて再現しただけ（段 3 の Tailscale のときに確かめる）。

## 気をつけること

- **この版を入れる最初のデプロイでは、一度だけログアウトされます。** 今のセッションはメモリにしかないためです。次のデプロイからはログアウトされません。
- 共用の端末では「ログインしたままにする」を選ばないでください。

## 確認したいこと

1. 期限は「選んだとき 30 日、選ばないとき 1 日（どちらも使うたびに延びる）」としました。この長さでよいですか。
