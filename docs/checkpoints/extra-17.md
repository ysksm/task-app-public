- スライド: [下書きから取り込む](../slides/req-draft.html)

## 決めたこと（オーナーに確かめたいもの）

| | 決めたこと | 理由 |
|---|---|---|
| 下書きの置き場 | プロジェクト（`projects.draft_of`）。キーは `TAPPD1` …。プロジェクト一覧・サイドバーには出さない | 今の画面と道具（MCP も）がそのまま下書きで使える。一覧が下書きで散らからない |
| 始め方 | 既定は **いまのマップの複製**。空からも選べる | 「今のマップを組み替える」試しがいちばん多いと考えた |
| 番号 | 複製は番号をそのまま（`TAPP-ST3` → `TAPPD1-ST3`）。下書きで足したものは取り込むときに取り込み先の番号が付く | 下書きと元を見比べやすい。取り込み先のキーは使い回さない |
| 照らし合わせ | 対応表（`req_draft_links`）で合わせる。名前では合わせない。ただしリリースのまとまりは同じ名前なら同じもの | 名前を変えても「消して新しく作った」にならない。空の下書きで「R1」と書けば、元の R1 に入る |
| 下書きで消したもの | 取り込み先でも**アーカイブ**する（消さない）。まとまりは、取り込み先にまだストーリーがあれば残して知らせる | 要求の層は消さずにアーカイブする決まり。黙ってストーリーを未定に落とさない |
| 元にしかないもの | 残す（予定に一覧だけ出す） | 複製のあとに元で足したものを、下書きが知らないだけで消さない |
| 両方で変わったもの | **衝突**として印を付け、「上書きして取り込む」を明示したときだけ取り込む（API は 409、`force` で上書き）。あいだに別の取り込みをはさんでも同じ | 元で直したことを黙って上書きしない |
| 元で変えて、下書きでは変えていない | 何もしない（元のまま） | 3 者比較。下書きの古い値で戻さない |
| 取り込む人 | **人だけ**（エージェントは 403）。エージェントは下書きを作り、予定を見せる | 受入検査と同じ考え。決めるのはオーナー |
| 取り込みの単位 | 予定に出たものを全部まとめて、1 つのトランザクションで | 「一気に入れたい」。途中で止まって半分だけ入ることがない |
| イシュー | 下書きにはつながりを複製しない。取り込みで元のつながりはそのまま残る | 下書きのプロジェクトにはイシューがない。つなぐのは取り込んだあと |
| 取り込んだあと | 下書きはそのまま使える。もう一度取り込むと、その後の違いだけが入る。いらなければ「下書きを捨てる」（アーカイブ） | 何度かに分けて決めていける |
| 書き方 | 下書きの既定は「まず書く（quick）」 | ブレスト向き。元が「整理して書く」なら、手順のない新しいストーリーは「未整理に入る」と予定に注意を出す |

## 確認済みのこと

- Go の単体テスト、API テスト 229 件（+13 `drafts.test.ts`。複製・空・予定・取り込み・もう一度取り込むと空・衝突と force・あいだに取り込みをはさんでも衝突が消えない・元にしかないもの・名前での照らし合わせ・名前がぶつかる注意・活動のアーカイブ・まとまりの名前の入れ替え・使われているまとまりは消さない・エージェントは 403・MCP）、画面テスト 48 件（+2 `storymap-drafts.spec.ts`）がすべて成功した。MCP の道具一覧とマップの形のテストに `create_draft`・`get_import_plan`・`draft_of` を足した。
- demo データで、下書きを作る → ひとことでストーリーを 2 つ足す・R2 を「つぎ」に変える・1 つ消す・タイトルを直す → 予定（増える 2・変わる 2・消える 1）→ 取り込む、を画面で確かめ、写真をスライドに載せた。
- 作っている途中で 2 つの誤りを見つけて直した（どちらもテストあり）。(1) まとまりの名前を入れ替えると（R1 ⇔ R2）両方のストーリーが同じ名前になった。(2) 取り込みのたびに、触っていない要素の対応表まで書き直していたので、元で変えた要素をあとで下書きで直すと、衝突の印が出ずに上書きされた。触っていない要素は対応表をそのまま残すようにした。
- ストーリーマップのヘッダーは横にスクロールするので、その中のポップオーバー（下書きのメニュー）が切れていた。ポップオーバーを画面に固定して出すようにし、「抜け」の一覧も同じ形にした。

## わかっている制限

- 項目ごとに選んで取り込むことはできない（全部か、取り込まないか）。
- 取り込みの取り消しはない（変更履歴には `from_draft` 付きで残る）。
- 2 つの下書きの間の比較はない。
- 下書きでまとまりの名前を、元にしかないまとまりの名前に変えると取り込めない（予定に注意を出し、取り込みは 409）。
- 下書きのプロジェクトのイシュー一覧などは開けば開ける（隠してはいるが、閉じてはいない）。

## 確認したいこと

1. 上の「決めたこと」でよいか（特に「人だけが取り込む」「下書きで消したものは元でもアーカイブ」「衝突は上書きを明示したときだけ」）。
2. 項目ごとに選んで取り込む形が要るか。
3. 本番の TAPP に入れる前に、ほかに試したいことがあるか（push・PR・デプロイは、指示をもらってから行う）。
