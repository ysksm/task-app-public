# ✅ 確認ポイント 1（P0 基盤 + P1 コア）

## 起動方法

必要なもの: Go 1.24+、Node 22+、pnpm

```bash
pnpm install          # 初回のみ
make build            # Web UI をビルドして bin/taskapp に埋め込む
make demo             # ~/.taskapp にデモデータを投入（初回のみ）
./bin/taskapp serve   # http://127.0.0.1:7700 を開く
```

- データを分けたい場合は `--data DIR` を付ける（例: `./bin/taskapp seed --data /tmp/tk --preset demo && ./bin/taskapp serve --data /tmp/tk`）。
- ブラウザはローカル単独モードで自動的にオーナーとしてログインする（デモでは Owner）。
- 開発時は `make dev-api`（:7700）と `make dev-web`（:5173、Vite）を並行して起動する。

デモデータ: プロジェクト `APP` に、エピック → ストーリー → フィーチャー → タスク → タスク の階層、QA 2 件、人間 2 人（Owner, Alice）、エージェント 2 体（Claude, Codex）。API トークンは `tk_demo_<ユーザー名>`（例: `tk_demo_claude`）。

## 確認していただきたい操作

1. **プロジェクト一覧**（サイドバー「プロジェクト」）: 進捗バーと種別ごとの件数。
2. **イシュー一覧**（サイドバー「タスク管理アプリ」）
   - 右上で **リスト / ボード / ツリー** を切り替える。
   - リスト: 「グループ」（ステータス / 担当者 / 種別 / 優先度）と「並び」を変える。
   - ツリー: エピック → … → タスクの下のタスク まで階層表示。▸ で折りたたみ。
   - ボード: カードをドラッグしてステータス変更。
3. **フィルタ**: 「フィルタ」から種別・担当者（自分 / 未割り当て / エージェントだけ / 人間だけ）・ステータス・優先度・ラベル。検索欄（`/` キー）、「完了を隠す」。条件は URL に残るので、リロードやブックマークで再現できる。
4. **イシュー詳細**（行をクリックすると右側に表示。⤢ で全画面）
   - パンくずに祖先の階層、子イシューと進捗、QA 未回答バッジ。
   - タイトル・説明（Markdown）・ステータス・優先度・担当・ラベル・親・期日・見積りをその場で編集。
   - 「親」の「変更」で付け替え。階層ルール違反や循環はエラーメッセージが出る。
   - アクティビティに変更履歴とコメント。エージェントの操作は経路（API / MCP など）付きで表示。
   - 「配下をツリー表示」アイコンで、そのイシュー配下だけを一覧に表示。
5. **イシュー作成**: どこでも `C` キー（または「＋新規」）。親キーを入れると、親に合った種別だけが選べる。
6. **マイタスク**: 「担当」「起票したもの」「回答待ち QA」タブ（全プロジェクト横断）。サイドバーに回答待ち QA の件数。
7. **リアルタイム反映**: 画面を開いたまま、別ターミナルからエージェントとして更新すると数秒以内に反映される。

   ```bash
   curl -X PATCH -H "Authorization: Bearer tk_demo_claude" -H "Content-Type: application/json" \
     -d '{"title":"エージェントが更新"}' http://127.0.0.1:7700/api/v1/issues/APP-4
   ```

## テスト

- `make test` … Go 単体テスト + API テスト（67 件）。
- API テスト（`apitest/`）は `bin/taskapp` を起動して HTTP だけで検証する。Rust 版でも `make test-api TASKAPP_BIN=/path/to/rust-binary` でそのまま使える。
- `apitest/tests/contract.test.ts` は、レスポンスが `api/openapi.yaml` の定義と一致するかを検証する。
