# ✅ 確認ポイント 2（P2: Jira REST API v3 互換 / ORCA 連携）

ORCA の Jira 連携（Cloud モード）から本アプリにつなげるよう、Jira REST API v3 互換の API（`/rest/api/3`、`/rest/agile/1.0`）を実装しました。

## 起動方法

```bash
make build
make demo-fresh        # /tmp/taskapp-demo に新しいデモデータを作って起動（http://127.0.0.1:7700）
```

- **7700 番で確認ポイント 3 のサーバー（P2 以前のバイナリ）が動いていたら必ず止めてください。** 古いバイナリには `/rest/api/3` がないため、ORCA からは 404 になります。
- `~/.taskapp` など P2 以前のデータもそのまま使えます（起動時のマイグレーションでメールアドレスが補完されます。`~/.taskapp` のコピーで確認済み）。
- ORCA の通信を見たいときは `--log-requests` を付けて起動します（パス・クエリ・ステータス・User-Agent がログに出ます）。

## ORCA からつなぐ

1. ORCA の **Settings → Jira** で接続方式に **Cloud** を選ぶ。
2. 次の値を入れる（本アプリの「設定 › Jira 互換 API（ORCA 連携）」にコピーできる形で出ています）。

| 項目 | 値（デモデータ） |
|---|---|
| サイト URL | `http://127.0.0.1:7700` |
| メールアドレス | `owner@taskapp.local` |
| API トークン | `tk_demo_owner`（自分用に発行したトークンでも可） |

エージェントの立場で試すときは `claude@taskapp.local` / `tk_demo_claude` を使います。

## 確認していただきたい操作

| ORCA での操作 | 本アプリ側で見えること |
|---|---|
| 接続 | 表示名「Owner」で接続される |
| タスク一覧（Assigned / Reported / Done / All、JQL 入力） | 自分の担当・起票・完了・全件が出る。種別は Epic / Story / Feature / Task / Question、ステータスは本アプリのものがそのまま出る |
| 詳細を開く | 説明（Markdown → ADF）とコメントが出る。エージェントの**チェックポイントは `[Checkpoint]` で始まるコメント**として並ぶ（APP-3 で確認できます） |
| 作成 | プロジェクト・種別（Epic / Story / Feature / Task）・要約・説明で作れる。本アプリの画面に即時に出て、履歴に「Jira API」と付く |
| ステータス変更・担当者・優先度・ラベル変更 | 本アプリに即時反映される |
| コメント | 本アプリのアクティビティに出る。1 行目を `[Checkpoint] 要約`、次の行以降を `判断基準: ...` などにするとチェックポイントとして記録される |
| 課題のリンク | `http://127.0.0.1:7700/browse/APP-3` が本アプリのイシュー画面に飛ぶ |

## 確認済みのこと

- API テスト 137 件（うち Jira 互換 32 件）と Go の単体テスト（JQL・ADF 変換）がすべて成功。
- **ORCA のコードを使った接続確認**: ORCA のソース（`stablyai/orca`）から Jira クライアント部分（認証つきリクエスト・ページ送り・イシュー / コメント / ステータスの解析・ADF 変換）を取り出し、通信だけを `fetch` に置き換えて本アプリにつないだ。接続 → プロジェクト一覧 → 4 種類の一覧 JQL → 詳細 → コメント → 遷移一覧とボードの列順 → 作成メタデータ → 作成 → 更新（要約・ラベル・優先度・担当・遷移・コメント）まで、ORCA 側の解析結果が正しいことを確認。
- `scripts/jira-smoke.sh` で curl から同じ流れを通し、画面で「Jira API」経由の履歴として反映されることを確認。

## 確認できていないこと

- **ORCA アプリ本体からの接続**（インストール済みの ORCA 1.4.224）。デスクトップアプリを操作する手段がないため、ここをお願いしたいです。
- 添付ファイル（`/attachment/content`）は未対応（404）。説明・コメント内の画像も表示されません。
- ORCA は ADF の太字やリンクを文字だけで表示するため、本アプリで書いた `**強調**` やリンクの URL は ORCA 上では装飾なしの文字になります（ORCA 側の仕様）。

## 決めたこと・補足

- **QA（Question）は Jira API から作成できません**（作成ダイアログに出さず、種別 Question での作成・種別変更は 400）。回答形式つきの質問は MCP の `ask_question` で起票します。
- QA は既定でオーナーの担当になるため、ORCA の「Assigned」一覧にも出ます。**回答は本アプリの画面でのみ**できます（ORCA の課題リンク `/browse/APP-8` から本アプリの回答画面に飛べます）。
- ORCA から QA のステータスを「回答済」に変えることはできますが、回答の入力は飛ばされます（回答内容は空のまま）。
- Jira 互換 API の仕様は `api/openapi.yaml` ではなく API テスト `apitest/tests/jira.test.ts` で固定しています（Rust に置き換えるときもこのテストで確認します）。
- 遷移は制約なし（どのステータスへも移れる）。通常のイシューには通常のステータス、QA には QA 用のステータスだけを出します。
- 優先度は Highest / High / Medium / Low の 4 つ。「優先度なし」は Jira 上は未設定（null）です。
- 既存ユーザーでメールアドレスがない場合は `<ユーザー名>@taskapp.local` を自動で設定しました（ORCA の Cloud モードはメールアドレス必須のため）。
- 階層は `fields.parent` で返します。ORCA は親を表示しないため、ORCA 上では階層は見えません。
