# ✅ 確認: デプロイの準備（追加作業 A-4）

サーバー上で、同じマシンのリバースプロキシ（`tailscale serve` など）の後ろで動かすための準備です。ブランチは `feat/deploy` です。

## 入れたもの

| 項目 | 内容 |
|---|---|
| `serve --behind-proxy` | 同じマシンのリバースプロキシ（`tailscale serve`）の後ろで動かすためのオプション。プロキシ経由の MCP（`/mcp`）が 403 にならないようにし、パスワードなしの自動ログインを止める（プロキシ経由だと、この PC からの接続かどうかを見分けられないため） |
| `serve --public-url URL` | 設定画面の「ほかの端末から使う」と MCP のコマンドに出す URL |
| 環境変数 `TASKAPP_OWNER` | 初回の起動で作るオーナーのユーザー名。サービス用のユーザー（`taskapp`）で動かしても、オーナーがその名前にならないようにする |

## 確認済みのこと

- 単体テスト（`TASKAPP_OWNER` を含む）、API テスト 180 件（うちプロキシの後ろ 4 件）、画面テスト 27 件がすべて成功。
- API テストで確かめたこと:
  - `--behind-proxy` なしでは、公開名の `Host` でループバックに届いた MCP が 403 になる。
  - `--behind-proxy` ありでは 200 になる。トークンがない・間違っているときは 401 のまま。
  - `--behind-proxy` では自動ログインが 403 になる。
  - `--public-url` の値が `remote_url` に出る。

## 確認できていないこと

- `tailscale serve` が転送するときの `Host` ヘッダーは、実物では確認していません（テストでは公開名の `Host` で再現）。
