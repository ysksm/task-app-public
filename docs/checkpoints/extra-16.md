- スライド: [案 E 実装](../slides/req-e.html) の後ろ 3 枚

## 決めたこと（オーナーに確かめたいもの）

| | 決めたこと | 理由 |
|---|---|---|
| まとまりの持ち方 | 新しい表 `req_releases`。ストーリーは今のまま名前（文字列）で指す | ストーリーの API を変えずに済む。名前を変えるとストーリーも付いてくる |
| 知らない名前 | ストーリーに書いた新しいリリース名で、まとまりが「計画中」でできる | まず書く の「R2 と書いて Enter」と MCP の `update_story` をそのまま使える |
| 状態 | 計画中 / 作っている / 出した を人が決める。進み具合（n/m 完了）は計算 | 「出した」は事実なので、ストーリーの完了からは決めない |
| 次に出す | いちばん上の「出した」でないまとまり。その行の上に線を地図の端まで引く | 地図の上の線 = ウォーキングスケルトン、のいつもの描き方 |
| 消す | ストーリーがないときだけ（あるときは 409） | 黙ってストーリーを「未定」に落とさない |
| キー | `TAPP-RL1`（`R` ではない） | 名前の「R1」とまぎれない（案 B で困ったところ） |
| 既定のまとまり | 作らない。まず書く の入力例だけ「いま / つぎ / あとで」 | 名前は人が決める |

## 確認済みのこと

- Go の単体テスト、API テスト 216 件（+6 `releases.test.ts`。MCP の道具一覧とマップの形のテストに `update_release`・`release_slices` を足した）、画面テスト 46 件（+2 `storymap-releases.spec.ts`）がすべて成功した。
- demo データの R1（ねらい「ログインして、ORCA から自分のタスクを読める」、作っている、目安あり）と R2（計画中）を地図で確かめ、写真をスライドに載せた。
- マイグレーション 012 は、ストーリーにすでに書かれたリリース名から、名前順にまとまりを作る。

## わかっている制限

- 出したまとまりは薄く出すだけで、畳まない。
- ストーリーをまとまりへドラッグできない（S16 の「リリース」に名前を書く）。
- S16 のリリース欄は自由入力のまま（今あるまとまりから選ぶ形にはしていない）。
- スプリントは地図に載せない。
