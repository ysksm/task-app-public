# ✅ 確認: MCP の登録先の選択と、トークンを後から表示（追加作業 A-5）

要望は 2 つです。

- 設定画面の MCP のコマンドを、Claude Code の登録先（スコープ）ごとにコピーしたい。
- トークンを発行したときだけでなく、後からも確認したい。コピーするコマンドにも入れてほしい。

トークンの扱いは「サーバーに暗号化して保存」を選んでいただきました。ブランチは `feat/mcp-scope` です。

## 入れたもの

| 項目 | 内容 |
|---|---|
| 登録先の切り替え | 設定 › エージェントの接続（MCP）に `user`・`local`・`project` のボタンを置いた。コマンドの `--scope` と、消すときのコマンドが切り替わる。初期値は `user` |
| project スコープ | `.mcp.json` は git に入るので、トークンを書かずに `${TASKAPP_TOKEN}` にし、`export TASKAPP_TOKEN=…` の行を出す |
| トークンの控え | 発行するときに、トークンを AES-256-GCM で暗号化して `api_tokens.token_enc` に保存する（マイグレーション 006）。鍵は `<data>/token.key` で、32 バイト・0600、初回の起動で作る。**認証には今までどおりハッシュだけを使う** |
| 表示の API | `POST /api/v1/tokens/{id}/reveal`。オーナーはすべてのトークン、ほかの人とエージェントは自分のトークンだけを読める。失効したトークンは 404 |
| 画面 | トークン一覧の目のボタンで表示する。表示したトークンが MCP と Jira のコマンドに入る。発行した直後も同じ |

## 確認済みのこと

- Go の単体テスト、API テスト 182 件、画面テスト 28 件がすべて成功した。
- API テストで確かめたこと:
  - 後から読んだ値が、発行したときの値と同じになる。CLI（seed）で作ったトークンも読める。
  - ほかのユーザーのトークンは 404 になり、トークンなしでは 401 になる。失効したトークンは 404 になる。
  - `token.key` を消してから起動すると、トークンでの認証は通るが、表示は 409 `not_available` になる。
- 画面テストで確かめたこと:
  - 発行したトークンがコマンドに入る。
  - 再読み込みしたあとに目のボタンで同じ値が出る。
  - スコープを切り替えるとコマンドが変わる。

## 気をつけること

- **セキュリティの決まりを変えました。** これまでは「トークンはハッシュだけ」でした。DB と `token.key` の両方が漏れると、トークンも漏れます。DB だけ、またはバックアップだけなら漏れません。
- **このしくみより前に発行したトークンは表示できません。** すでに使っているトークンも同じなので、表示したいものは発行し直してください。
- **`token.key` は、DB のバックアップにも JSON のエクスポートにも入りません。** 復元したあとも表示したいときは、データディレクトリの `token.key` も一緒にコピーしてください。なくても、トークンでの認証はそのまま使えます。
  - 取り込み（`taskapp import`）の場合は、新しいデータディレクトリに `token.key` を置きます。取り込みの前でも後でもかまいません。
- `token.key` は、この版で最初に起動したときに作られます。持ち主はサービス用のユーザー（`taskapp`）です。
  - 鍵が読めないときも、taskapp は止まりません。警告を出して動き続けます。ただし、その間に発行したトークンは後から表示できません。
  - root で直接 `taskapp … --data /var/lib/taskapp` を実行して鍵を作ってしまうと、この状態になります。CLI を使うときは `taskapp-ctl` か `runuser -u taskapp` を通します。

## 確認したいこと

1. スコープの初期値は `user` でよいですか。
2. 表示できるのは「オーナーと、トークンの持ち主」としました。エージェントは自分のトークンだけを読めます。この範囲でよいですか。
