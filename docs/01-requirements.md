# 01. 要求仕様書

| 項目 | 内容 |
|---|---|
| 文書バージョン | 0.1 (ドラフト / レビュー待ち) |

| 対象 | AIエージェントと人間の協働タスク管理アプリ (仮称: task-app) |

---

## 1. 目的・背景

AIコーディングエージェント（Claude Code / Codex 等）と人間が同じプロジェクトを進めるとき、次の問題が起きる。

- エージェントが **何をどこまで進めたか、なぜその判断をしたか** が後から追えない
- エージェントが判断に迷った点が人間に届かず、勝手に決めるか止まってしまう
- 人間側のプロジェクト管理（エピック/ユーザーストーリー）、QA、受入検査が、エージェントの作業単位とつながっていない

本アプリは、**人間のプロジェクト管理とエージェントの作業記録を1つの階層データで管理する** ことでこれを解決する。

- UI と内部データは **Linear ライク**（高速、キーボード操作中心、シンプルなステータス/ビュー）
- 外部 API は **Jira REST API v3 互換** とし、**ORCA** (https://www.onorca.dev/) の Jira 連携（Cloud モード）からそのまま接続できるようにする
- AI エージェント向けに **MCP サーバー** を内蔵し、チェックポイント記録や QA 起票をツールとして提供する

## 2. 用語・解釈

| 用語 | 意味 |
|---|---|
| チケット / イシュー | 本アプリで管理する作業単位の総称。種別 (エピック/ユーザーストーリー/フィーチャー/タスク/QA) を持つ |
| エピック | 大きな目的・テーマ。最上位の階層 |
| ユーザーストーリー | 利用者視点の要求。「〜として〜したい、なぜなら〜」 |
| フィーチャー | ストーリーを実現する機能単位 |
| タスク | 実作業単位。タスクの下にタスクを無制限にネスト可 |
| QA チケット | エージェントが人間に確認したい事項（質問）。人間が回答する |
| チェックポイント | エージェントが作業途中に残す進捗記録。「何をしたか / 何を判断したか / 判断基準 / 次に何をするか」を含む |
| 受入検査 | ストーリー/フィーチャーが受入基準を満たすか人間が判定する工程 |
| ORCA | stablyai/orca。コーディングエージェントを並列実行する開発環境。Jira/Linear/GitHub のタスクから worktree を作ってエージェントを起動できる |
| MCP | Model Context Protocol。エージェントがツールとして本アプリを操作するためのプロトコル |

依頼文の解釈:
- 「MindMap楓」→ **マインドマップ風の表示** と解釈
- 「プロジェクト後に書く画面ではフィルターができ」→ **プロジェクトごとの各画面でフィルターができる** と解釈

## 3. 利用者（アクター）

| アクター | 説明 | 主な操作 |
|---|---|---|
| 人間: プロジェクト管理者 | エピック・ストーリーを定義し、全体進捗を見る | エピック/ストーリー作成、優先度付け、マインドマップで全体確認 |
| 人間: 開発者 / QA 回答者 | エージェントの質問に答え、作業をレビューする | QA 回答、自分の担当確認、レビュー |
| 人間: 受入検査者 | 完成した機能を受け入れるか判定する | 受入基準チェック、合格 / 差し戻し |
| AI エージェント | タスクを実行し、進捗と判断を記録する | タスク取得、ステータス更新、チェックポイント記録、QA 起票、子タスク作成 |
| ORCA | エージェント実行環境。Jira クライアントとして本アプリに接続 | イシュー検索・閲覧・作成・遷移・コメント |

利用形態は **ローカル単独**（個人 PC 上で起動）。人間ユーザーは主に 1 名（オーナー）だが、データ上は複数の人間/エージェントを区別できるようにする。

## 4. 機能要求

### 4.2 チケット階層

| ID | 要求 | 優先度 |
|---|---|---|
| HIE-01 | 種別は **エピック / ユーザーストーリー / フィーチャー / タスク / QA** | M |

| HIE-03 | タスクの下にタスクを配置でき、深さに制限はない（循環は禁止） | M |

| HIE-05 | 親を付け替えられる（ドラッグ＆ドロップまたは親選択）。規則違反は拒否する | M |
| HIE-06 | 親チケットに子孫の進捗（完了数/総数）を集計表示する | M |
| HIE-07 | 階層の途中を飛ばした親子（例: エピック直下のタスク）を許可するかはプロジェクト設定で切替可 | S |

標準の親子規則（○: 子にできる）:

| 親 \ 子 | ストーリー | フィーチャー | タスク | QA |
|---|---|---|---|---|
| (なし=ルート) | ○ | ○ | ○ | ○ |
| エピック | ○ | ○ (*1) | ○ (*1) | ○ |
| ストーリー | × | ○ | ○ (*1) | ○ |
| フィーチャー | × | × | ○ | ○ |
| タスク | × | × | ○ | ○ |
| QA | × | × | × | × |

エピックはルートのみ。ルートの QA は人間が単独で起票する質問・メモ用（エージェントの QA は QA-01 のとおり対象チケットの子として作る）。(*1) は HIE-07 の「スキップ許可」が ON のとき有効（デフォルト ON）。

#### 4.7.1 QA の質問と回答形式

人間が素早く答えられるよう、エージェントは質問の内容に合った回答形式を指定して起票する。**1 つの QA チケットに複数の質問**を入れられ、質問ごとに回答形式を選ぶ（2026-10-11 のレビューで決定）。

| 回答形式 `answer_type` | 用途 | 選択肢 | 人間側の UI | エージェントが受け取る値 |
|---|---|---|---|---|
| `yes_no` | 「〜してよいですか？」などの可否 | 「はい / いいえ」（固定） | 2 つのボタン | `selected_option_ids`: `["yes"]` / `["no"]` |
| `ok_ng` | 確認・承認（「この方針で OK？」） | 「OK / NG」（固定） | 2 つのボタン | `["ok"]` / `["ng"]` |
| `single_choice` | 2〜6 択から 1 つ（2 択・3 択・4 択など） | エージェントが指定（`id`, `label`, 説明, 推奨フラグ） | 選択肢カード（推奨に印） | 選んだ選択肢 1 つ |
| `multi_choice` | 2〜6 個から当てはまるものを**複数選択** | 同上 | チェック付きカード | 選んだ選択肢すべて |
| `text` | 自由記述が必要な質問 | なし | テキスト入力 | `text` |

- どの形式でも補足コメント（`note`）を任意で入力できる。`single_choice` / `multi_choice` では「その他（自由記述）」を許可できる（`allow_other`）。
- 質問ごとに必須 / 任意を指定できる（`required`、既定は必須）。
- 一部の質問だけ先に回答して保存できる。**必須の質問がすべて回答されると「回答済」**になる。クローズするまでは回答を修正できる。
- 回答の検証はサーバー側で行う（存在しない選択肢、単一選択で複数、テキスト形式で空回答などは拒否）。
- エージェントの読み取り: MCP `get_question_answers` / API `GET /api/v1/qa/{key}` で次の形を返す。

```json
{
  "key": "APP-22", "status": "answered", "is_blocking": false, "target_key": "APP-4",
  "items": [
    {
      "question": "セッションの有効期限はどれにしますか？", "answer_type": "single_choice",
      "options": [{ "id": "a", "label": "1日" }, { "id": "b", "label": "7日", "recommended": true }, { "id": "c", "label": "30日" }],
      "answer": {
        "selected_option_ids": ["b"], "selected_options": [{ "id": "b", "label": "7日" }],
        "text": null, "note": null,
        "answered_by": { "username": "owner", "kind": "human" }, "answered_at": "2026-10-11T14:02:00.000Z"
      }
    },
    {
      "question": "『ログイン状態を保持する』を付けてよいですか？", "answer_type": "ok_ng",
      "answer": { "selected_option_ids": ["ok"], "note": "共有端末では OFF を既定に", "...": "..." }
    }
  ]
}
```

### 4.8 受入検査

| ID | 要求 | 優先度 |
|---|---|---|
| ACC-01 | ストーリー/フィーチャーに **受入基準**（チェックリスト）を定義できる | M |
| ACC-02 | 受入待ちのチケットを受入検査画面で一覧できる | M |
| ACC-03 | 受入検査者は基準ごとに OK/NG とコメントを記録し、**合格**（→ Done）または **差し戻し**（→ In Progress、差し戻し理由を記録）を判定する | M |
| ACC-04 | 受入検査の履歴（回数、判定、検査者、日時）を残す | M |
| ACC-05 | 判定時に、配下の未完了の子チケットや未回答 QA があれば警告する | S |

**決定（2026-10-12）**
- 受入基準を持てるのはストーリーとフィーチャー。基準を編集・削除しても、過去の判定には判定時の文言が残る。
- 判定できるのは人間だけ（エージェントは `request_acceptance` で受入待ちにするまで）。差し戻しには理由（総評）が必須で、NG の基準があるときは合格にできない。
- 合格 → 最初の「完了」カテゴリのステータス、差し戻し → 最初の「進行中」カテゴリのステータス（受入待ち以外）へ移す。
- 未完了の子イシュー・未回答 QA がある場合、合格は警告を確認したうえで「それでも合格」にしたときだけ通る。
- エージェントは MCP の `get_issue` で受入基準と直近の判定（差し戻し理由・NG の基準）を読める。

### 4.10 Jira 互換 API（REST API v3 / ORCA 連携）

**決定（2026-10-11）: Jira REST API v3（`/rest/api/3`）互換で実装する。** v3 は最新の Jira API（Jira Cloud 系）で、ORCA の「Cloud」接続モードがこれを使う。ORCA は接続先 URL を `*.atlassian.net` に限定していないため、`http://127.0.0.1:7700` を Cloud モードの接続先として登録できる。v2（Server/DC 互換）は今回のスコープ外とし、必要になれば同じ変換レイヤーに追加する。

| ID | 要求 | 優先度 |
|---|---|---|
| JIRA-01 | Jira **REST API v3** (`/rest/api/3/...`) 互換のエンドポイントを提供する | M |
| JIRA-02 | ORCA の Jira 連携（Cloud モード）で接続・一覧・詳細・作成・更新・遷移・コメントが動作する | M |
| JIRA-03 | 認証: **Basic（メールアドレス + API トークン）**。ORCA の Cloud モードは常にこの方式。加えて Bearer（API トークン）も受け付ける | M |
| JIRA-04 | JQL のサブセットをサポートする（§4.10.2） | M |
| JIRA-05 | 未対応のエンドポイント/JQL は Jira 形式のエラー（`errorMessages`）で返す | M |
| JIRA-06 | 説明・コメントは **ADF（Atlassian Document Format）** で入出力し、内部の Markdown と相互変換する | M |

#### 4.10.1 対象エンドポイント（ORCA ソースコード調査に基づく）

ORCA (`stablyai/orca` `src/main/jira/`、調査したリビジョン `3b49ee40` / 2026-10-11) が Cloud モード（v3）で呼ぶもの:

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/rest/api/3/myself` | 接続確認・自分の情報（`accountId`, `emailAddress`） |
| GET | `/rest/api/3/serverInfo` | サーバー情報（汎用クライアント向け） |
| GET | `/rest/api/3/project/search` | プロジェクト一覧（`startAt`/`maxResults`/`isLast` のページング、`values` 配列） |
| POST / GET | `/rest/api/3/search/jql` | JQL 検索（`jql`, `maxResults`, `fields`, `nextPageToken`） |

#### 4.10.2 JQL サポート範囲

ORCA が生成する JQL（例: `assignee = currentUser() AND resolution = Unresolved ORDER BY updated DESC`、`key = "APP-1"`、`text ~ "foo*"`）を必ず処理できること。

- フィールド: `project`, `key`/`issuekey`, `issuetype`/`type`, `status`, `statusCategory`, `assignee`, `reporter`, `priority`, `labels`, `parent`, `resolution`, `text`, `summary`, `created`, `updated`
- 演算子: `=`, `!=`, `in`, `not in`, `~`, `!~`, `is EMPTY`, `is not EMPTY`, `>`, `>=`, `<`, `<=`
- 論理: `AND`, `OR`, `NOT`, 括弧
- 関数: `currentUser()`
- `ORDER BY <field> [ASC|DESC], ...`
- `resolution = Unresolved` は「カテゴリが completed/canceled 以外」として扱う
- ユーザーの指定は `accountId`（= 内部ユーザー ID）、メールアドレス、ユーザー名のいずれでも受け付ける

#### 4.10.3 データの対応付け

| 本アプリ | Jira v3 表現 |
|---|---|
| 種別 エピック/ストーリー/フィーチャー/タスク/QA | issuetype `Epic`/`Story`/`Feature`/`Task`/`Question`（固定 ID、`hierarchyLevel` も返す） |
| 親子（任意の深さ） | `fields.parent` に親の `{id,key,fields:{summary,status,issuetype}}`。タスク配下のタスクも同様 |
| ステータス + カテゴリ | `status` + `statusCategory`（new / indeterminate / done） |
| canceled / completed | `resolution` (`Won't Do` / `Done`) |
| 説明・コメント (Markdown) | **ADF** に変換して返す（段落・見出し・リスト・コード・リンク・強調）。受信した ADF は Markdown に変換して保存 |
| ユーザー | `accountId`（= 内部ユーザー ID）, `displayName`, `emailAddress`, `active`, `accountType`（人間 `atlassian` / エージェント `app`） |
| チェックポイント | 読み取り時はコメント（1 行目が `[Checkpoint] #N 要約` の ADF）として表示。`[Checkpoint]` で始まるコメントの投稿はチェックポイントとして取り込む（下記） |
| 優先度 | `Highest`(1)=緊急 / `High`(2)=高 / `Medium`(3)=中 / `Low`(4)=低。優先度なしは `priority: null` |
| ID | プロジェクト・イシュー・コメントの `id` は数値文字列（10000 から採番）。`accountId` は内部ユーザー ID |

**作成できる種別（決定 2026-10-12）**: Jira API からはエピック / ストーリー / フィーチャー / タスクを作成できる。QA（Question）は回答形式つきの質問が必要なため MCP の `ask_question` からのみ起票する（`createmeta` に出さない）。

**`[Checkpoint]` コメントの書式**: 1 行目が `[Checkpoint] 要約`、続く行に `判断:` `判断基準:`（必須）`代替案:`（`/` 区切り）`確信度: 高|中|低` `進捗: 40%` `次:` を書く（英語のラベル `Decision` `Rationale` なども可）。判断基準がないと 400 を返す。

### 4.12 複数端末からの利用

## 5. 非機能要求

| ID | 区分 | 要求 |
|---|---|---|
| NFR-01 | 配布 | **単一バイナリ**で起動（Web UI 同梱）。追加ミドルウェア不要 |
